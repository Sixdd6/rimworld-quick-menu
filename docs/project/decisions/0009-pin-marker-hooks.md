# 0009. Pin marker: a postfix on Command.GizmoOnGUIInt for buttons, float-menu option postfixes for dropdown entries, and a reference-identity pinned set

- **Status**: accepted (2026-10-19; FR-19 is approved, the orchestrator or the user may still revise the open points at the end)
- **Date**: 2026-10-19

## Context

FR-19 (Should): a small pin marker on every architect button that is currently pinned, on a dropdown button when the whole dropdown is pinned, and on pinned single entries inside an open dropdown list. It must update on the next frame after a pin or unpin and must cost nothing measurable per frame (NFR-1; budget P-19: at most 100 ns and 0 bytes per gizmo draw call). User decisions 11–13 (plan.md, 2026-10-19) and the user rule for this spike:

- **11**: when only single entries of a dropdown are pinned, the dropdown button shows a **smaller** marker. A whole-dropdown pin shows the normal marker.
- **14** (user, 2026-10-19, after the T-89 preview): the partial marker is **white** instead of dimmer blue, to show that a pin is inside the dropdown.
- **12**: the marker appears in the **architect menus only**, never on copy/build buttons in the command bar of selected things.
- **13**: pins hidden beyond the current capacity are **not** marked.
- **User rule**: the marker must work in **all three** architect menus (vanilla Architect tab, Better Architect Menu (BAM), Dubs Mint Menus' build menu) and **nowhere else**.

Existing patch sites (architecture section 6): (1) `UIRoot_Play.UIRootUpdate` postfix, (2) prefixes on every `Designator*.ProcessInput` override, (3) `Designator_Dropdown.GetDesignatorSelectAction` postfix (wraps each entry's action in our `EntryAction`). Pin gestures are accepted only while an architect menu is open (`PinClickPatch.IsArchitectTabOpen`: the vanilla tab, which BAM draws into, or Mint's `MainTabWindow_MintArchitect` / `MainTabWindow_MayaMenu` on the window stack).

### Findings (offline, ilspycmd on RimWorld 1.7.4982 `Assembly-CSharp.dll`, BAM workshop 3563882422 `1.6/Assemblies/BetterArchitect.dll` (the only build; it loads on 1.7 through the shim), Mint `reference/1.7/Assemblies/DubsMintMenus.dll`; decompiled into `/tmp`, nothing in the repo; for BAM and Mint only behaviour and type/method names were noted)

- **top-left**: the hotkey letter (`x + 5, y + 3`, Tiny font; architect build designators get `entDef.designationHotKey`, orders have their own keys); the Steam Deck "A" glyph (`21 × 21`) on the first gizmo.

**BAM.** BAM's Harmony prefix on `ArchitectCategoryTab.DesignationTabOnGUI` replaces the vanilla drawing (returns `false`). It still runs inside `MainTabWindow_Architect.ExtraOnGUI` (so `OpenTab == Architect` and `currentlyDrawnWindow == null`), in a scroll view. `DrawFlatGrid`, `DrawGroupedGrid` and `DrawOrdersPanel` call `Gizmo.GizmoOnGUI(topLeft, 75, parms)` for each designator, so they reach `Command.GizmoOnGUIInt` with a 75 × 75 rect, and clicks go to `ProcessGizmoInteractions` → virtual `ProcessInput` (as found in S-3). A dropdown click therefore opens the **vanilla** float menu or float grid through `Designator_Dropdown.ProcessInput`. Two BAM specifics: (a) its optional special Floors tab flattens floor dropdowns and draws their `Designator_Build` elements as **standalone buttons** (the dropdown button is not shown; dropdowns with an eyedropper stay dropdowns); (b) in BAM's edit mode it draws small edit buttons at `(xMax − 14, y + 2, 12 × 12)` expanded by 2 (top-right, `y` to `y + 16`), and its debug order overlay uses the bottom 14 px. BAM's "mystery unlock" option draws some locked designators itself instead of calling `GizmoOnGUI`. BAM's edit mode can create its own `Designator_Build` instances (`new Designator_Build(def)`) for buildables added to categories, so the instance BAM draws is not always the one in `DesignationCategoryDef`.

**Mint's build menu.** It is a separate `MainButtonDef` ("MintMenus", `tabWindowClass` `DubsMintMenus.MainTabWindow_MintArchitect`); Mint's `MainTabsRoot.ToggleTab` prefix swaps the Architect button to it (Ctrl reverses the choice). So while it is open, `OpenTab` is that def (not Architect, not Inspect), and it draws inside its window body, so `currentlyDrawnWindow` **is** the Mint window. Mint itself uses `currentlyDrawnWindow is MainTabWindow_MintArchitect` as its own "am I drawing the build menu" test. Two views:
- **Grid view (Mint's default, `BuildListMode = false`)**: `Gizmo.GizmoOnGUI(position, width, default parms)` per designator → reaches `Command.GizmoOnGUIInt` with a 75 × 75 rect. After it, Mint draws a sort-value bar over the top 16 px (only while a sort stat is chosen) and a 16 × 16 "in wheel" ring at the top-left for designators on its wheel. A click goes to `Gizmo.ProcessInput`; for a dropdown Mint then finds the new `FloatMenu`/`FloatMenuGrid` and, with its default "auto close" setting, **replaces every option's `action`** with its own closure that runs the old action and closes the window.
- **List view (`BuildListMode = true`)**: rows draw only `Command.DrawIcon(icon rect)` plus labels; `GizmoOnGUI`/`GizmoOnGUIInt` are **not** called.
- Mint's wheel (`MainTabWindow_MayaMenu`) and its designator bars (drawn from a `MainButtonsRoot.MainButtonsOnGUI` prefix, outside any window) are not architect menus under the user rule.

**Command bars of selected things (decision 12).** `MapGizmoUtility.MapUIOnGUI` draws the selection's gizmo grid only when `OpenTab` is `null` or `Inspect`. `BuildCopyCommandUtility.BuildCommand` returns a fresh `Command_Action` in general, but for a stuff-made buildable with no stuff it returns **the architect's own `Designator_Build` instance** (`FindAllowedDesignator`, cached from `AllResolvedAndIdeoDesignators`). So reference identity alone does not exclude command bars; a context check is needed, and the `OpenTab` rule makes it cheap: in vanilla and BAM no command bar is drawn while the Architect tab is open, and none is drawn while Mint's build tab is open.

**Dropdown entry lists.** `Designator_Dropdown.ProcessInput(Event)` builds either `SetupFloatMenu` (a `FloatMenu` of `FloatMenuOption(designator.LabelCap, GetDesignatorSelectAction(ev, designator), icon…)`) or `SetupGridMenu` (a `FloatMenuGrid` of `FloatMenuGridOption(icon, GetDesignatorSelectAction(ev, designator), …)`, plus an eyedropper option for carpets), adds it to the window stack, then selects the active element. Hidden elements are skipped. Our site 3 postfix already wraps each returned action in `EntryAction(entry, original)`, so for vanilla and BAM `option.action.Target` is our `EntryAction`; under Mint (auto close on) it is Mint's closure. Draw methods:
- `FloatMenuOption.DoGUI(Rect rect, bool colonistOrdering, FloatMenu floatMenu)`: `public virtual bool`, no overrides in the game; called by `FloatMenu.DoWindowContents` once per option per event (inside the float menu window, with `rect` the option row). Row layout (private constants): icon square at `(x + 4, y + 4)` to `(x + CurIconSize, y + CurIconSize)` where `CurIconSize` is 27 (Normal) or 16 (Tiny), shifted 4 px right while hovered; label from `x + 6 + iconOffset` to `xMax − 10` (the widest option's label can reach that end); `extraPartOnGUI` gets a zero rect when `extraPartWidth` is 0, so it cannot carry our drawing.
- `FloatMenuGridOption.OnGUI(Rect rect)`: `public bool`, not virtual; 34 × 34 cells; background, fitted icon, invisible button; no corner overlays. It has a `postDrawAction` hook (vanilla does not set it for dropdowns).
- BAM opens the vanilla menus (above). Mint opens the vanilla menus too, but rewraps the actions.

## Options considered

### Buttons (hook site 4)

1. **Postfix on `Command.GizmoOnGUIInt(Rect, GizmoRenderParms)`** (chosen). One method; the exact button rect is a parameter (also for shrunk gizmos); reached by vanilla, all three BAM grids and Mint's grid view. The call into it is virtual, so JIT inlining is not a concern. Cons: runs for every command in every command bar, so the fast path must be a few ns for non-designators; the marker is drawn before the overrides draw the "+" and before BAM/Mint draw their own overlays, so the corner must avoid those. Mod designators that override `GizmoOnGUIInt` without calling the base get no marker.
2. **Postfix on `Designator.GizmoOnGUI`** (the base; every vanilla override calls it). Fewer calls (designators only). Cons: the rect must be rebuilt (`topLeft`, virtual `GetWidth`); the overrides reach it through a non-virtual base call, which a JIT could inline; misses the shrunk path and `GizmoOnGUIInt`-only callers.
3. **Postfix on `Command.DrawIcon` and its declared overrides.** The only option that also reaches Mint's list view. Cons: needs one patch per override (`Command`, `Designator_Build`, `Designator_Dropdown`, `Designator_Paint`, plus mods); `Designator_Dropdown.DrawIcon` calls the active element's `DrawIcon` with the button rect, so a single-entry pin would draw the full marker on the dropdown button (needs a nesting counter, i.e. prefixes too); runs inside our own wheel, Mint's wheel and Mint's bars (needs a context filter on every call); only the icon rect is known. Rejected for v1 (see "Mint list view" below).
4. **Prefix/postfix around `ArchitectCategoryTab.DesignationTabOnGUI` to set a "drawing the architect" flag**, plus option 1. Precise for vanilla/BAM, but BAM's prefix skips the original, and it does not cover Mint. The `OpenTab`/`currentlyDrawnWindow` check below gives the same answer without a patch. Rejected.

### Dropdown entries (hook site 5)

1. **Option → entry map filled when the menu opens, plus draw postfixes on `FloatMenuOption.DoGUI` and `FloatMenuGridOption.OnGUI`** (chosen). A postfix on `Designator_Dropdown.ProcessInput` runs right after the vanilla code added the menu window and **before** Mint rewraps the actions, so it can read `option.action.Target is EntryAction` reliably and key the map by the **option object**, which Mint does not replace. Draw postfixes then do one identity lookup per option.
2. **Read `option.action.Target` at draw time** (no map, no ProcessInput postfix). Works for vanilla and BAM, fails under Mint with its default "auto close" (the target is Mint's closure). Unwrapping Mint's closure by reflection couples us to Mint internals. Rejected.
3. **Set `FloatMenuGridOption.postDrawAction`** at open instead of patching the grid option. No patch for the grid, but the list `FloatMenuOption` has no equivalent (its `extraPartOnGUI` gets no rect), so a patch is needed anyway; one pattern for both is simpler to review and to fault-inject. Rejected.
4. **Match options to entries by order or label** at first draw. Fragile (eyedropper option, hidden elements, sorting by priority). Rejected.

### Pinned lookup

1. **Reference-identity map `designator → PinMark` (`None`, `Full`, `Partial`), plus a `BuildableDef → Full` map for build pins**, rebuilt off the hot path (chosen). O(1), allocation-free (`Dictionary` with `ReferenceEqualityComparer`, `TryGetValue`).
2. **Compute `PinKey.For(designator)` per draw and look it up in the board.** Allocates strings and walks the catalog. Rejected (NFR-1).
3. **Identity map only.** Misses BAM's own `Designator_Build` instances (edit mode) and any mod that draws a clone. The def map fixes this for build pins at the cost of a second lookup on a miss. Rejected as the only map.

## Decision

### Draw context: "an architect menu is drawing" (shared by sites 4 and 5)

`ArchitectDrawContext.IsActive()` (adapter, allocation-free, called only after a lookup hit):

```
Window w = Find.WindowStack.currentlyDrawnWindow;
if (w == null) return Find.MainTabsRoot.OpenTab == MainButtonDefOf.Architect;   // vanilla and BAM (ExtraOnGUI)
return ModDetection.Mint && w.GetType() == mintArchitectType;                    // Mint build menu (window body)
```

`mintArchitectType` is resolved once by name (`DubsMintMenus.MainTabWindow_MintArchitect`, as `PinClickPatch` already does) and compared by reference. This excludes command bars of selected things (never drawn while either tab is open, decision 12), our own Quick Menu window, Mint's wheel and Mint's designator bars (decision "nowhere else"). It deliberately differs from the pin-gesture gate, which also accepts Mint's wheel window: the marker is not drawn there. Accepted edge: a third-party mod that draws architect designators with `GizmoOnGUIInt` outside any window while the vanilla Architect tab is open would also show markers.

### Hook site 4: architect buttons (task T-91)

- **Patch**: Harmony **postfix** on `Verse.Command.GizmoOnGUIInt(Rect, GizmoRenderParms)` (protected virtual; resolved with `AccessTools.Method(typeof(Command), "GizmoOnGUIInt", new[] { typeof(Rect), typeof(GizmoRenderParms) })`; a missing method is `Site.Fail`, not a crash). No transpiler.
- **Signature**: `static void Postfix(Command __instance, Rect __0)`. `__instance` is the declaring type (Harmony 3 type check); the rect is bound by index (`__0`), not by the game's name `butRect`.
- **Body** (patch-guard convention, cheapest test first, nothing allocates):
  1. `if (Site.Disabled || PinnedDesignators.IsEmpty) return;`
  2. `try {`
  3. `if (__instance is not Designator d) return;` (pawn and building commands stop here: one flag, one count, one type check)
  4. once per frame (`Time.frameCount != _lastFrame`): `DesignatorCatalog.RefreshIdeology()` (its O(1) signature check; a real refresh is rare and rebuilds the set through the catalog's normal path, see Invalidation) and a version compare that rebuilds the set if a rebuild was missed (safety net; normally a no-op).
  5. `PinMark mark = PinnedDesignators.Lookup(d); if (mark == PinMark.None) return;` (identity map, then the def map if `d is Designator_Build`)
  6. `if (Event.current.type != EventType.Repaint) return;`
  7. `if (!ArchitectDrawContext.IsActive()) return;`
  8. draw the marker (below) with `GUI.DrawTexture`, saving and restoring `GUI.color`.
  9. `} catch (Exception ex) { Site.Fail(ex); }` (logs once, disables the site; the gizmo was already drawn and keeps working).
- **What gets which mark**: a pinned designator drawn as its own button → `Full`. A dropdown whose whole dropdown is pinned → `Full`. A dropdown with no whole pin but at least one shown, pinned single entry → `Partial` (smaller, white; decisions 11 and 14). A single entry drawn as its own button (BAM's flattened Floors tab) → `Full`; in that tab the dropdown button itself is not drawn, so a whole-dropdown pin of a flattened floor dropdown shows no marker there.
- **Corner (all three menus, UI scale 1–2)**: the **top-right column, directly under the vanilla "+" slot**. With `k = butRect.height / 75` and marker size `s` (design.md, T-89; about 0.2 × 75 = 15 UI px at full size):
  `markerRect = (butRect.xMax − 1·k − s, butRect.y + 18·k, s, s)`.
  The partial marker uses the same top-right anchor point (same right edge and top) with its smaller size. Why here: top-left holds the hotkey letter, the Steam Deck glyph and Mint's "in wheel" ring; the top 16–17 px on the right hold the "+", BAM's edit buttons and Mint's sort bar; the bottom holds the label strip (up to 20 px into the button for two lines) and BAM's debug overlay. The band `y + 18 … y + 33` on the right edge is free of all of them; it overlaps only the outer corner of the icon, as the "+" does, which the marker's `rimOutline` keeps legible. All values are in UI units, so the game's UI scale is applied by IMGUI; the texture is rasterized at `s × Prefs.UIScale` screen px (T-89). Shrunk gizmos (36 px) scale by `k`.
- **Mint list view**: **not supported in v1** (no marker). Mint's list rows never call `GizmoOnGUI`/`GizmoOnGUIInt`; supporting them needs option 3 (patches on every `DrawIcon` override plus nesting prefixes). Mint's default grid view is supported. Listed as a known limit (T-79) and reported to the user before T-91 starts; it can be added later as a site 6 if the user wants it.

### Hook site 5: entries in an open dropdown list (task T-92)

- **5a (map fill)**: Harmony **postfix** on `RimWorld.Designator_Dropdown.ProcessInput(Event)`: `static void Postfix(Designator_Dropdown __instance)`. Under the guard: if `!ArchitectDrawContext.IsActive()` return (dropdowns opened elsewhere get no markers). Find the top-most `FloatMenu` or `FloatMenuGrid` on `Find.WindowStack` (scan from the top). If it is the menu already mapped, return (this also covers the case where site 2's prefix skipped the original for a pin gesture, since Harmony still runs postfixes). Otherwise clear the map and, for each option whose `action?.Target` is our `EntryAction` whose entry is in `__instance.Elements`, add `option → entry`. Storage is reused (`Clear`, not `new`); allocation is allowed here (once per open). This runs before Mint's code rewraps the actions, and the map is keyed by the option object, which Mint keeps. `EntryAction` exposes its entry as a read-only property (T-92).
- **5b (list rows)**: **postfix** on `Verse.FloatMenuOption.DoGUI(Rect, bool, FloatMenu)`: `static void Postfix(FloatMenuOption __instance, Rect __0)`.
- **5c (grid cells)**: **postfix** on `Verse.FloatMenuGridOption.OnGUI(Rect)`: `static void Postfix(FloatMenuGridOption __instance, Rect __0)`.
- **5b/5c body**: `if (Site.Disabled || _map.Count == 0) return; try { if (!_map.TryGetValue(__instance, out Designator entry)) return; if (PinnedDesignators.LookupEntry(entry) != PinMark.Full) return; if (Event.current.type != EventType.Repaint) return; draw; } catch → Site.Fail`. Options of any other float menu (right-click menus, orders, other mods) stop at the empty map or one failed `TryGetValue`. No context check is needed at draw time: the map only ever holds options of a dropdown opened from an architect menu.
- **Entry marker rule**: an entry is marked when the **entry itself** is pinned (single-entry pin). A whole-dropdown pin marks no entries (`LookupEntry` uses the identity map only; the def map is not used here, so it cannot leak a mark onto other entries).
- **Corners**: list row: the top-right corner of the option's icon square, using vanilla's layout (`CurIconSize` 27 for Normal, 16 for Tiny, read once per draw through a cached `AccessTools.FieldRefAccess` to the private `sizeMode` field; Normal if the field is missing, logged once; `+4` px x-shift while the row is hovered and enabled): `iconRect = (x + 4 [+4], y + 4, CurIconSize − 4, CurIconSize − 4)`, marker `s_row ≈ 0.45 × iconRect.width` at `(iconRect.xMax − s_row, iconRect.y)`. Rows without an icon (rare: only non-`Designator_Place` elements) get the marker at the row's right end, centred vertically; the widest label of such a menu may touch it (accepted). Grid cell: top-right corner, `(xMax − 1 − s_cell, y + 1)`, `s_cell ≈ 0.3 × 34`. Sizes are design.md's (T-89).
- **Next-frame update**: an entry pin toggled by modifier+click goes through site 3 (`EntryAction`), which rebuilds the set synchronously; the option's next `DoGUI` reads the new state. (Vanilla closes the float menu after any option click, so this is visible only when the list is reopened or stays open.)

### Pinned lookup (Core rules in T-90, adapter wrapper `PinnedDesignators` in T-91)

- **Core** `PinnedSet<T> where T : class` holds `Dictionary<T, PinMark>` with `ReferenceEqualityComparer.Instance` (`PinMark` = `None`, `Full`, `Partial`). `Lookup(T?)` returns the mark (null → `None`), allocation-free and O(1). `Rebuild(...)` clears and refills the same dictionary (no new storage after the first build at the same size) and increments `Version`. The builder takes the board, a resolver (key → instance or none, and for an element, its dropdown parent) and the visibility rule, all supplied by the adapter. Core still references no game type.
- **Adapter** `PinnedDesignators` has two sets: `PinnedSet<Designator>` (identity) and `PinnedSet<BuildableDef>` (def map, `Full` only). `Lookup(Designator d)`: identity first; on `None` and `d is Designator_Build b`, the def map for `b.PlacingDef`. `LookupEntry(Designator d)`: identity only.
- **Membership rules** (for each pin the menu **shows**, decision 13: exactly the pins `PinBoard.VisibleSlots` returns as `Resolved`: Fixed, slots `0 … Capacity − 1`; Auto, the resolved pins; computed with a non-allocating loop that the tests check against `VisibleSlots`):
  - `build:` / `order:` pin resolving to designator `X`: `X → Full`; for `build:` also `X.PlacingDef → Full` in the def map. If `X` is an element of dropdown `P` (from the catalog's tree), `P → Partial` unless `P` is already `Full`.
  - `dropdown:` / `moddrop:` pin resolving to dropdown `P`: `P → Full` (overrides `Partial`). Its elements get nothing.
  - unresolved, opaque, missing-mod and hidden-beyond-capacity pins: nothing.
- **Which instance**: keys resolve through the catalog key map to the instances the catalog collected from `DesignationCategoryDef.AllResolvedDesignators` / `AllIdeoDesignators` (and dropdown children). These are the instances the vanilla architect, BAM's grids and Mint's grid draw, and the same instances `BuildCopyCommandUtility.FindAllowedDesignator` returns (it caches from `AllResolvedAndIdeoDesignators`). Build designators drawn as other instances (BAM edit-mode categories, mods that clone) are caught by the def map. If a `build:` key matches more than one catalog instance (duplicate keys, counted by the self-test), the def map marks all of them.
- **Invalidation** (each calls `PinnedDesignators.Rebuild()`; the per-gizmo path only reads, and the hook's once-per-frame step can trigger a rebuild only in the two rare cases at the end of this item): every pin toggle (`PinService`, by architect click, dropdown entry or menu slot), settings load, `ApplyCapacity` (layout, sizing mode, rings, columns, rows), sizing-mode switch, "Forget missing pins", static catalog build, and every Ideology refresh that changed the catalog (`DesignatorCatalog.Version` increments). An edit-mode swap or move does not change membership, so it needs no rebuild (a rebuild there is harmless). Safety net: the hook's once-per-frame step compares `DesignatorCatalog.Version` and a board version with the values of the last build and rebuilds only on a mismatch. The once-per-frame `RefreshIdeology()` call exists because a newly loaded game creates new Ideology designator instances, and nothing else refreshes the catalog until the menu is opened or a pin gesture happens; its cost is the existing O(1) signature check, once per frame and only while command gizmos are being drawn.

### Cost (P-19, T-88)

Non-designator command: one static flag, one count, one type check (a few ns). Designator not pinned: plus one frame compare and one or two dictionary lookups (well under 100 ns). Pinned designator: plus the event type, the context check and two `GUI.DrawTexture` calls (outline and mark) on Repaint only. Zero allocations on every path (no LINQ, closures, boxing or strings). Float menus: one count check per option per event, plus one `TryGetValue` while a mapped dropdown list is open. Measured by the T-90 Perf test (lookup) and the dev-mode counter and `MeasureScope` in T-91.

## Consequences

- Five patch sites instead of three: site 4 is one method; site 5 is three methods (5a, 5b, 5c). Still no transpilers and no patches on BAM, Mint or Multiplayer code. The self-test lists each as patched or failed, and each has a fault-injection point (T-72).
- Site 4 runs for every command gizmo the game draws (including command bars while the architect is closed), so its fast path is a hard performance contract (P-19). Sites 5b/5c run for every float-menu option drawn anywhere; their fast path is one count check.
- The marker works in the vanilla Architect tab, in BAM (flat, grouped and orders grids; flattened Floors tab entries are marked as buttons) and in Mint's build menu grid view. **Not supported**: Mint's list view (known limit), Mint's wheel and designator bars (by design), mod designators that draw their own `GizmoOnGUIInt` without calling the base (known limit; the self-test lists `Designator` subclasses that declare `GizmoOnGUIInt`), and BAM's "mystery" placeholders (no real button is drawn).
- Plan follow-ups for the planner (this ADR does not edit plan.md): T-91's criterion "rebuilt … never by the hook" is relaxed to "never on the per-gizmo path"; the once-per-frame step may rebuild after an Ideology change or a missed invalidation. T-90's criteria say a single-entry pin puts "its dropdown not" in the set and that hidden-beyond-capacity pins "are still members"; per user decisions 11 and 13 they become "its dropdown gets `Partial`" and "hidden-beyond-capacity pins are not members", plus the def map. T-92's file list gains `DropdownEntryPatch.cs` (expose the entry). The vanilla row-layout constants used for the list corner are private and could change between game builds; UC-6 checks the corner.
